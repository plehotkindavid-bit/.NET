# ID Convention

## 1. Project ID

`ECOM-CORES`

## 2. Stable Core ID

Format:

`CORE-{NAME}-{NUMBER}`

Examples:
- `CORE-HEADLINER-001`
- `CORE-MANAGER-001`
- `CORE-PRODUCT-001`
- `CORE-STOCK-001`
- `CORE-RULES-001`
- `CORE-PRICE-001`
- `CORE-ORDER-001`

The ID remains stable when text or code changes. The semantic version changes instead.

## 3. Operation ID

Every runtime workflow receives a unique operation ID, preferably a GUID/UUID generated by ASP.NET Core.

Example:

`0f8fad5b-d9cb-469f-a165-70867728950e`

This ID connects logs from Product, Stock, Price, and Order cores for the same request.

## 4. Idempotency key

A client-created or server-created key prevents duplicate orders when the same request is retried.

Example:

`order-create-customer-42-cart-813-v1`

## 5. Git identity

Git does not require a custom ID inside every file. Git identifies file history through paths, commits, branches, and hashes. Core IDs are application-level identifiers, not a replacement for Git commit hashes.
